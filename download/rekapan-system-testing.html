BAB 1

Pendahuluan

1.1 Latar Belakang

Sistem Informasi Pencatatan Nama Bayi Baru Lahir merupakan aplikasi berbasis web yang dikembangkan untuk mendukung proses pencatatan data kelahiran di Kabupaten Ngada, Provinsi Nusa Tenggara Timur. Sistem ini dirancang untuk menghubungkan Puskesmas sebagai sumber data kelahiran dengan Dinas Kependudukan dan Pencatatan Sipil (Dukcapil) yang berperan dalam verifikasi dan penerbitan dokumen kependudukan. Dengan adanya sistem ini, diharapkan proses pencatatan kelahiran yang sebelumnya dilakukan secara manual dapat terdigitalisasi sehingga lebih efisien, akurat, dan terintegrasi.

Sebelum sistem ini diimplementasikan secara penuh di lingkungan Dukcapil Kabupaten Ngada, diperlukan tahap system testing yang komprehensif untuk memastikan bahwa seluruh fungsi sistem berjalan sesuai dengan spesifikasi yang telah ditetapkan. Pengujian ini menjadi bagian penting dari siklus pengembangan perangkat lunak, khususnya sebagai bukti dukung bahwa sistem telah memenuhi standar kualitas yang diharapkan sebelum digunakan oleh pengguna akhir.

Dokumen ini menyajikan rekapan hasil system testing secara terstruktur, mencakup pengujian fungsional, non-fungsional, maupun teknis yang dilakukan pada lingkungan produksi sistem. Hasil pengujian ini dapat digunakan sebagai lampiran bukti dukung dalam laporan pelaksanaan kegiatan pengembangan sistem informasi.

1.2 Tujuan Pengujian

Pengujian sistem ini dilakukan dengan beberapa tujuan utama yang mencakup aspek kualitas, keandalan, dan keamanan sistem. Berikut adalah tujuan pengujian secara rinci:

  1. Memverifikasi fungsionalitas sistem — Memastikan seluruh fitur utama sistem berjalan sesuai dengan spesifikasi kebutuhan, termasuk proses autentikasi pengguna, pengelolaan data kelahiran, verifikasi data oleh admin, serta fitur pelaporan dan analitik.
  2. Mengevaluasi performa sistem — Mengukur waktu respon sistem dalam melayani permintaan pengguna, khususnya pada proses pemuatan halaman, pengiriman formulir, dan pengambilan data dari server.
  3. Menguji keamanan sistem — Memastikan bahwa mekanisme autentikasi dan otorisasi berfungsi dengan baik, serta tidak terdapat kerentanan keamanan yang dapat dieksploitasi oleh pihak tidak berwenang.
  4. Memvalidasi responsivitas antarmuka — Memastikan bahwa tampilan sistem dapat beradaptasi dengan baik pada berbagai ukuran layar perangkat, mulai dari desktop, tablet, hingga perangkat mobile.
  5. Mengidentifikasi celah aksesibilitas — Mengevaluasi sejauh mana antarmuka sistem mendukung aksesibilitas bagi pengguna dengan keterbatasan, termasuk penggunaan markup HTML semantik dan atribut ARIA.

1.3 Ruang Lingkup Pengujian

Ruang lingkup pengujian mencakup seluruh modul dan komponen yang terdapat dalam Sistem Pencatatan Bayi Baru Lahir. Secara garis besar, pengujian dilakukan pada area-area berikut:

Cakupan Pengujian: Halaman publik (Landing Page, Login), Dashboard Admin Dukcapil, Dashboard Operator Puskesmas, Autentikasi dan otorisasi, API endpoints (55+ endpoint), Basis data PostgreSQL (6 tabel utama), Keamanan aplikasi, Performa dan responsivitas, Aksesibilitas antarmuka, serta Kompatibilitas lintas browser.

Pengujian dilakukan pada lingkungan produksi dengan URL https://pencatatan-bayi.vercel.app yang di-deploy melalui platform Vercel. Database menggunakan layanan Supabase PostgreSQL yang berlokasi di cloud, sehingga pengujian mencerminkan kondisi penggunaan sistem yang sesungguhnya.

Setiap kasus uji dievaluasi berdasarkan kriteria kelulusan yang telah ditetapkan sebelumnya. Kriteria ini menjadi acuan dalam menentukan apakah sistem memenuhi standar kualitas yang diharapkan. Berikut adalah kriteria kelulusan yang digunakan dalam pengujian ini:

Hasil Pengujian Non-Fungsional

Pengujian non-fungsional mengevaluasi aspek kualitas sistem yang tidak terkait langsung dengan fungsionalitas spesifik, melainkan dengan bagaimana sistem bekerja secara keseluruhan. Aspek yang diuji mencakup responsivitas tampilan, performa waktu muat, keamanan, serta aksesibilitas antarmuka pengguna. Hasil pengujian non-fungsional memberikan gambaran mengenai pengalaman pengguna dan keandalan sistem.

4.1 Pengujian Responsif (Responsive Design)

Pengujian responsif dilakukan untuk memastikan antarmuka sistem dapat menyesuaikan tampilannya dengan baik pada berbagai ukuran layar perangkat. Pengujian dilakukan pada tiga breakpoint utama yang mewakili perangkat desktop, tablet, dan smartphone. Hasil pengujian menunjukkan bahwa sistem memiliki desain responsif yang baik dengan adaptasi layout yang tepat pada setiap ukuran layar.

ID Uji Nama Uji Hasil Deskripsi Pengamatan
TC-11 Tampilan desktop (1920x1080) PASS Landing page menampilkan layout penuh dengan hero, kartu fitur, statistik, dan CTA. Login page menampilkan layout dua kolom (sidebar + form). Semua elemen terlihat proporsional.
TC-12 Tampilan mobile (375x667) PASS Landing page menumpuk secara vertikal, CTA tetap dapat diakses. Login page menyembunyikan sidebar, hanya menampilkan header + kartu login. Field dan tombol tetap dapat digunakan.
TC-13 Tampilan tablet (768x1024) PASS Layout serupa desktop namun lebih ringkas. Login page menyembunyikan sidebar, menampilkan header + kartu login. Semua elemen interaktif tetap dapat diakses.

4.2 Pengujian Performa

Pengujian performa mengukur kecepatan pemuatan halaman dan waktu respon server pada lingkungan produksi. Pengukuran dilakukan menggunakan tools pengembang browser dengan memperhatikan metrik-metrik utama seperti Page Load Time, DOM Content Loaded, dan Transfer Size. Hasil pengujian menunjukkan performa yang sangat baik, jauh melampaui ambang batas yang ditetapkan.

ID Uji Nama Uji Hasil Ambang Batas Hasil Pengukuran
TC-14 Load time landing page PASS < 5 detik 287 ms (loadEventEnd). DOM content loaded: 283 ms. Transfer: 6.476 bytes. Decoded body: 24.961 bytes.
TC-15 Load time halaman login PASS < 3 detik 85 ms (loadEventEnd). DOM content loaded: 43 ms. Transfer: 300 bytes (cached). Decoded body: 24.970 bytes.

Kecepatan ini menunjukkan efektivitas optimasi Next.js (server-side rendering, code splitting, caching) yang diterapkan pada sistem.

Hasil pengujian menunjukkan bahwa sistem memiliki tingkat keamanan yang baik untuk aplikasi tingkat pemerintahan.

4.4 Pengujian Aksesibilitas

Pengujian aksesibilitas mengevaluasi sejauh mana antarmuka sistem mendukung aksesibilitas bagi seluruh pengguna, termasuk pengguna dengan keterbatasan fisik. Aspek yang dievaluasi mencakup penggunaan markup HTML semantik, atribut ARIA, serta ketersediaan teks alternatif untuk elemen visual. Pengujian ini mengidentifikasi beberapa area yang memerlukan perbaikan untuk meningkatkan aksesibilitas sistem secara keseluruhan.

ID Uji Nama Uji Hasil Deskripsi Pengamatan
TC-19 Struktur HTML semantik FAIL Tidak ditemukan elemen <main>, <header>, atau <nav> pada kedua halaman (landing dan login). Konten dibungkus dengan <div> generik. Hal ini menghalangi navigasi landmark pada screen reader. Rekomendasi: Gunakan elemen semantik untuk meningkatkan aksesibilitas.
TC-20 Atribut aksesibilitas pada SVG FAIL Tidak ada elemen <img> pada halaman. Semua ikon menggunakan SVG. 10 dari 11 SVG di landing page dan 15 dari 17 SVG di login page memiliki aria-hidden="true" (benar untuk ikon dekoratif). Namun, 3 SVG tidak memiliki aria-hidden maupun aria-label. Rekomendasi: Tambahkan aria-hidden="true" pada semua SVG dekoratif.
TC-47 Atribut lang pada HTML PASS Atribut <html lang="id"> telah diset dengan benar, menunjukkan bahasa konten adalah Bahasa Indonesia.
TC-48 Label pada form input PASS Semua field input pada formulir login memiliki elemen <label> yang terasosiasi dengan baik menggunakan atribut for atau nesting.
TC-49 Kontras warna teks PASS Kontras warna antara teks dan latar belakang memenuhi rasio minimum WCAG 2.1 Level AA (rasio 4.5:1 untuk teks normal, 3:1 untuk teks besar).
Temuan Aksesibilitas: Dua temuan gagal (TC-19, TC-20) bersifat Medium Priority dan tidak menghalangi fungsi utama sistem. Kedua temuan ini berkaitan dengan standar aksesibilitas WCAG dan dapat diperbaiki pada iterasi pengembangan berikutnya tanpa mengganggu operasional sistem.

BAB 5

Hasil Pengujian Teknis

Pengujian teknis mengevaluasi komponen infrastruktur dan arsitektur sistem yang mendasari fungsionalitas aplikasi. Aspek yang diuji mencakup ketersediaan dan kebenaran respons API endpoints, integritas skema basis data, serta kompatibilitas tampilan pada berbagai browser. Pengujian ini memberikan keyakinan bahwa fondasi teknis sistem telah dibangun dengan kokoh dan dapat diandalkan untuk mendukung operasional sehari-hari.

5.1 Pengujian API Endpoints

Sistem memiliki lebih dari 55 API endpoints yang terorganisir dalam 4 grup utama: Auth (autentikasi), Admin (manajemen admin), Operator (operasional puskesmas), dan BPJS (integrasi BPJS Kesehatan). Pengujian dilakukan untuk memverifikasi ketersediaan, keamanan akses, dan kebenaran respons dari setiap endpoint. Seluruh endpoint divalidasi terhadap skema Zod untuk memastikan integritas data yang masuk dan keluar.

No Grup API Jumlah Hasil Keterangan
1 Auth (/api/auth/*) 6 endpoints PASS NextAuth.js, profil, ubah password, aktivitas terakhir. Session JWT dan RBAC berfungsi.
2 Admin (/api/admin/*) 25 endpoints PASS CRUD users, puskesmas, birth-records, verify, reject, NIK bayi, audit logs, analytics, export, charts, pengaduan, reports.
3 Operator (/api/operator/*) 12 endpoints PASS CRUD birth-records, upload files, stats, chart, recent records, import/export, pengaduan.
4 BPJS (/api/bpjs/*) 3 endpoints PASS View records, export, stats. Akses terbatas untuk role BPJS.
5 Utility (/api/*) 4 endpoints PASS Root route, seed data, setup, sync-schema.
