   954→    <div class="sub-title">6.2 Schema Synchronization Engine</div>
   955→    <div class="body-text">
   956→        Sistem menggunakan mekanisme unik yang disebut Schema Synchronization Engine untuk mengelola evolusi skema database tanpa menggunakan Prisma migration tradisional. Komponen ini diimplementasikan dalam file src/lib/schema-sync.ts dan bekerja dengan koneksi PostgreSQL langsung (bukan melalui Prisma Client) untuk menjamin keandalan bahkan ketika Prisma client mengalami masalah. Mesin ini beroperasi dengan dua mekanisme penting: pertama, time-based cache selama 10 menit yang mencegah sinkronisasi berulang dalam waktu singkat, dan kedua, deduplication yang memastikan hanya satu proses sinkronisasi yang berjalan pada satu waktu meskipun ada panggilan bersamaan.
   957→    </div>
   958→    <div class="body-text">
   959→    Proses sinkronisasi melakukan langkah-langkah berikut secara berurutan: (1) menambahkan kolom yang belum ada menggunakan ALTER TABLE ADD COLUMN IF NOT EXISTS, (2) memastikan kolom nullable benar menggunakan DROP NOT NULL, (3) memperbaiki nilai NULL pada kolom is_deleted, (4) memastikan keberadaan tabel audit_logs, birth_record_files, dan pengaduan beserta constraint dan indeksnya, serta (5) menambahkan foreign key yang mungkin belum ada. Pendekatan idempotent ini memungkinkan sinkronisasi dijalankan berkali-kali tanpa menyebabkan error, sehingga aman dipanggil pada setiap request API.

  1067→    <div class="body-text">
  1068→    Di samping komponen shadcn/ui yang digunakan secara luas, sistem memiliki beberapa komponen kustom yang dikembangkan khusus untuk kebutuhan aplikasi. Komponen SessionProvider membungkus NextAuth dengan konfigurasi refetchInterval dan refetchOnWindowFocus untuk menjaga sesi tetap segar. Komponen SessionTimeoutWarning menangani logika peringatan timeout sesi yang mendekati masa berlaku. Komponen ThemeToggle menyediakan toggle tema gelap/terang dengan animasi CSS, sementara SortableHeader menyediakan header tabel yang dapat diurutkan dengan indikator arah sorting. Selain itu, terdapat custom hooks seperti useTableSort untuk sorting tabel dengan persistensi URL, useMobile untuk deteksi viewport mobile, dan useClientSort sebagai alternatif sorting di sisi klien.</div>
